# 热键恢复与跨屏定位：验证说明

## 自动验证

在 Windows PowerShell 5.1、Visual Studio 2022 Build Tools 和 .NET Framework 4.8 targeting pack 环境下，从仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -RunTests
```

该入口先编译图标生成器、Comb 和 Probe，再编译和执行两组回归测试。GitHub Actions 的 Windows 工作流执行相同命令，只有全部成功后才上传编译包。某一次提交的执行结果以该次 Actions 运行记录为准。

| 范围 | 自动验证内容 | 边界 |
|---|---|---|
| Windows 构建 | 使用实际 .NET Framework 4.8 引用程序集编译完整程序 | 构建通过不代表界面或外设验收通过 |
| 热键恢复 | 将生产 `DoubleCtrlHook.cs` 与 Win32 测试替身一起编译，以 AnyCPU 和 x86 分别运行，检查安装失败、恢复、重复通知、定时器 ID 和停止行为 | 替身不会安装真实全局键盘钩子，也不会让电脑睡眠 |
| 窗口定位 | 调用生产 `WindowPlacement.cs` 的尺寸和边界计算，检查跨屏、负坐标与较小工作区 | 几何测试不能替代真实显示器、WPF 渲染或 DPI 验证 |

自动测试不需要 Everything，不修改它的配置，不模拟用户按键，不切换前台窗口。测试程序只在构建时使用，不包含在最终运行的 Comb.exe 中。

## Windows 实机验收

以下项目需要在空闲的测试电脑上实际执行。当前没有提供这些项目已完成的证据，不应因自动构建或回归测试通过而勾选。

### 1. 正常启动与热键

- [ ] 在本机从待验收的 PR 提交执行 `build.ps1 -RunTests`，记录提交 SHA 和实际构建结果；核对生成的 Comb.exe 产品版本为 0.1.1、文件版本为 0.1.1.0。
- [ ] 启动 Comb，确认托盘、搜索条、搜索结果和概览可打开。
- [ ] 退出其他同样使用双击 Ctrl 的工具，双击 Ctrl 呼出，再次双击隐藏；连续重复时，每次手势只触发一次。
- [ ] 在其他程序中使用 Ctrl+C、Ctrl+V，确认不会因此误呼出 Comb。
- [ ] 托盘中的「重新启用双击 Ctrl」执行后，快捷键仍然只触发一次，托盘显示正常状态。
- [ ] 在搜索条、结果与概览中分别检查 Enter、Ctrl+Enter、Esc 和鼠标操作。

### 2. 真实睡眠与唤醒

- [ ] 保持 Comb 常驻，让 Windows 真正进入睡眠；唤醒并解锁后检查双击 Ctrl、托盘打开搜索和实际搜索。
- [ ] 重复睡眠与唤醒，确认没有双触发、无响应或恢复提示反复出现。
- [ ] 如果设备支持并使用休眠，再独立验证休眠恢复。不要把锁屏、关闭显示器或模拟电源广播计为睡眠验证。
- [ ] 在自动重试或手动重试期间退出 Comb，确认进程能退出，退出后不会再次出现托盘提示。

若某设备出现失败，记录操作系统版本、睡眠类型、复现步骤和托盘显示的错误信息；用户可自行记录，Comb 仍不写日志文件。

### 3. 多显示器与较小工作区

- [ ] 两屏相同缩放：在左屏呼出，把窗口拖到右屏，再输入搜索词或切换结果/概览；窗口留在右屏。
- [ ] 结果与概览相互切换：当前尺寸能放入工作区时，位置和大小保持不变。
- [ ] 鼠标移到另一屏，但窗口不移动：切换结果/概览时，窗口不会跟随鼠标跳屏。
- [ ] 隐藏后重新呼出：窗口按鼠标所在屏幕定位。
- [ ] 副屏位于主屏左侧或上方：检查负坐标布局，窗口不被拉回主屏。
- [ ] 较窄竖屏或高缩放的小工作区：检查窗口边缘和主要操作能否触及。
- [ ] 普通工作区的展开窗口保留 680 个 WPF 逻辑单位的默认最小宽度；小工作区不足时仍按可用空间收缩，不重新撑出屏幕。
- [ ] 100% / 150% 或 200% 混合缩放：分别呼出、拖动和切换，检查尺寸、位置和点击区域。
- [ ] 外屏拔插或更换主屏后，再次呼出及切换形态，确认窗口可见。

本次维持现有的 system-DPI 模式。不同缩放比例显示器上的文字清晰度限制仍然存在；不能把位置修复视为已完成逐显示器 DPI 适配。
